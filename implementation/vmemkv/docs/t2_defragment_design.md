# T2 Defragment設計

T2のStorage Fragmentation(T1から参照されなくなった旧版・削除済み版の蓄積)を、
前景スレッドを止めずに解消する設計。T1 shardingの背景ワーカー方式と同型。

## 単位

- T2を固定8MBのセグメントに分割する。
- ページ単位の穴埋めは行わない。生死混在ページから死だけ抜くことはできないため。

## 手順

1. garbage率の最も高いセグメントを1つ選ぶ。
2. そのliveレコードだけ新tailへappendし直す。
3. T1のoffsetを新位置へ付け替える(世代管理下)。
4. 旧セグメント全体を空きとして切り離す。

## 並行性

- 前景読は止めない。移動前後どちらの版を見ても正しい値が返る。
- 前景書との競合はT1付け替えの世代管理で吸収する。
- manifest境界の前進とのみ排他する。
- 背景ワーカーはT1のプールを共用する。前景スレッドにcompactionを代行させない。

## 起動・停止

- 許容space overheadを唯一の公開パラメータとする(既定20%)。
- 全体garbage率が上限を超えたら開始、下限を下回ったら停止する。
- 対象選択はgreedy固定(最悪セグメント1つ)。帯域制限はcheckpoint間隔に連動させる。

## パラメータ

| Parameter | Meaning | Default |
| --- | --- | --- |
| `T2DefragSpaceOverheadPercent` | 許容space overhead(%)。起動・停止の唯一の判定基準 | 20 |

セグメントサイズ(8MB)、ワーカー共用、greedy選択は固定値とし、調整ノブに出さない。
