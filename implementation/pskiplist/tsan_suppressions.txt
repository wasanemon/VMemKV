# ThreadSanitizer suppressions for pskiplist.
#
# Usage: TSAN_OPTIONS="suppressions=$(pwd)/tsan_suppressions.txt" ./build/tests/test_pskiplist
#
# Suppression matching requires symbolization, which needs a working external symbolizer
# subprocess (llvm-symbolizer). In at least one sandboxed environment this hung indefinitely
# ("Can't read from symbolizer at fd N"); pointing TSAN_OPTIONS at `addr2line` instead worked:
# TSAN_OPTIONS="suppressions=... external_symbolizer_path=$(which addr2line)"
#
# read_value()/write_value_locked() (skiplist.hpp) implement a seqlock over each node's `value`:
# write_value_locked() mutates it with a plain (non-atomic) write while a concurrent read_value()
# may be reading it with a plain read. This is a real race in the C++ abstract-machine sense, but
# the seqlock's version-check-before/after retry loop discards any read that overlapped a
# concurrent write -- a torn read is never actually used, only retried. This is the same pattern
# (and the same suppression-over-annotation tradeoff -- `AnnotateBenignRaceSized` isn't available
# in either toolchain this project builds with) as vmemkv's own T2FlatFile record seqlock; see
# that project's tsan_suppressions.txt for the precedent.
#
# Verified empirically: the 5 concurrency stress test cases in tests/normal/test_concurrent.cpp,
# 30/30 clean runs each under this suppression, plus a custom-struct Value (wider than 8 bytes,
# widening the torn-write window) exercised the same way with zero corrupted reads observed.
race:*write_value_locked*
race:*read_value*
